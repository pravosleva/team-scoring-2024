## `getCondited`

`linearForecast`: Теперь он не берет скорость "с потолка". Он автоматически вычисляет, сколько дней прошло с момента самой первой созданной/обновленной задачи в pointset до currentDate, находит средний темп системы за всю историю и умножает его на ваш коэффициент.

`sensedSpeed` теперь строго коэффициент: Если вы передаете 1, расчет идет по чистой базовой скорости. Если 0.95 — скорость уменьшается на 5%. Если 1.2 — увеличивается на 20%.

## Пример результата:
```json
"adaptiveForecast": {
  "title": {
    "analytic": "Прогноз по текущему темпу",
    "engineer": "Адаптивный прогноз",
    "manager": "Прогноз по исторической скорости"
  },
  "daysLeft": 12,
  "text": "2026-06-22",
  "descr": "Динамический расчет на основе периода...",
  "recommendations": {
    "tasksPerDay": 2.5,
    "daysPerTask": 0.4,
    "hoursPerTask": 10,
    "descr": "Рекомендация для PM: чтобы закрыть оставшиеся 30 задач за 12 дн., необходимо сдавать по 2.5 задач в день (или тратить не более 0.4 дн. на одну задачу)."
  }
}
```

## Продуктовый смысл новых метрик
- Расчет от штук (абсолютных значений): Рекомендация высчитывается не из абстрактных процентов, а из реального остатка задач (totalTasks - condited). Это переводит планирование на язык физического бэклога.
- `tasksPerDay`: Если показатель равен, например, 2.5, PM понимает, хватает ли текущих ресурсов команды (или пропускной способности конвейера) на закрытие такого объема посуточно.
- `daysPerTask`: Этот параметр (Cycle Time) идеален для инженеров. Значение 0.4 дня означает, что задача не должна находиться в статусе "In Progress" дольше ~3-4 рабочих часов.

### Пояснения
* **Если календарь НЕ ПЕРЕДАН (`null`)**: В тексте инженера подставятся чистые технические фразы вроде: *«Это накладывает ограничение на средний Cycle Time задач...»*, а в поле рекомендации часы посчитаются по стандартным астрономическим суткам (24 часа) и выведутся с пометкой `(~X ч)`.
* **Если календарь ПЕРЕДАН**: Внутрь текста динамически добавится фраза: *«С учетом вашего рабочего расписания (8 ч/день)...»*, а расчет часов перестроится на бизнес-метрики и выведется в формате `(~X чистых раб. ч)`.
